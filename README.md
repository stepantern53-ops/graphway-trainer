# GraphWay

Тренажёр функций для школьников 7-9 классов: ученик меняет коэффициенты формулы, сразу видит новый график и прокладывает роботу безопасную дорогу к батарее.

**Работающий сайт:** https://graphway-game.ru

В проекте два эпизода - 12 линейных трасс `y = kx + b` и 12 квадратичных `y = ax² + bx + c`, `a ≠ 0`. Аккаунты, сессии и прогресс настоящие: данные хранятся в PostgreSQL, прохождение подтверждается сервером.

## Как устроена игра

- После регистрации сразу открывается первая трасса `L01` с доступной теорией, без обязательного приветствия.
- График перестраивается во время ввода, без отдельной кнопки проверки. Неполное число убирает кривую и блокирует запуск.
- Ввод принимает точные дроби и десятичную запятую без округления поля. Ранние трассы допускают ползунки, точные - только ручной ввод.
- Фиксированный коэффициент показывается заполненным и недоступным для правки, но его можно выделить и скопировать.
- Кнопка «Пуск» замораживает снимок коэффициентов в памяти и запускает поездку. Запрос сохранения уходит только после прибытия: сервер заново проверяет доступ и математику, затем идемпотентно записывает прохождение.
- Порядок уровней берётся из каталога: `L01` не имеет предыдущего, `L12` ведёт в `Q01`, после `Q12` показывается выбор трасс.
- Эпизод с параболами закрыт до завершения линейного эпизода, но его карточку можно рассмотреть.
- Теория необязательна: она не подставляет числа в поля и не создаёт скрытых условий.
- Телефон рассчитан на горизонтальную ориентацию. Портретный режим показывает инструкцию и не теряет введённые значения.

Введённые коэффициенты нигде не сохраняются: ни в localStorage, ни в базе. После перезагрузки или повторного входа поля возвращаются к начальным, а пройденные трассы и текущий уровень остаются.

## Стек

TypeScript, React 19 и Vite, CSS Modules, SVG; Node.js и Express; PostgreSQL с Drizzle и `pg`; Zod для схем запросов и ответов; Passport Local, Argon2id, `express-session` с хранилищем в PostgreSQL; KaTeX для формул; Three.js и React Three Fiber для объёмного робота; Vitest и Playwright для тестов.

## Решения, которые стоит объяснить

**Одна математика на клиенте и сервере.** `packages/math-core` не зависит от DOM, базы и React. Ни `eval`, ни CAS, ни проверка по пикселям: вердикт считается по коэффициентам. График дискретизируется только для отрисовки и никогда не участвует в решении.

**Сервер не доверяет клиенту.** Прохождение принимается после проверки владельца сессии, доступа к трассе и повторного расчёта математики. Запись идемпотентна, поэтому повторная отправка не создаёт дубль.

**Честная обработка сессии.** Ошибка CSRF обновляет токен, но не повторяет изменение автоматически: ученик сам повторяет сохранение. Другой аккаунт очищает прежнее состояние и требует входа. Истёкшая сессия отличается от обычной ошибки сети.

**Портретный режим не ломает состояние.** Инструкция перекрывает интерфейс, не размонтируя его, поэтому открытие клавиатуры на телефоне не считается поворотом устройства.

**3D-робот не влияет на игру.** Модель декоративная: при отсутствии WebGL, ошибке рендера или потере контекста показывается статичное изображение, а управление остаётся рабочим. При неактивной вкладке и при системном ограничении анимации рендер останавливается.

## Локальный запуск

Нужны Node.js 24, npm и Docker для PostgreSQL. Команды выполняются из корня репозитория.

```bash
npm ci
docker compose -f compose.graphway.local.yml up -d
```

Локальные секреты генерируются скриптом `scripts/local-env.ps1` (PowerShell) и не попадают в репозиторий. Дальше:

```bash
npm run db:migrate      # применить миграции
npm run admin:provision # создать администратора, если нужен полный доступ
npm run build
npm start
```

Приложение откроется на `http://127.0.0.1:3001`. Для разработки с горячей перезагрузкой:

```bash
npm run dev
```

Этот режим поднимает backend на 3001 и Vite на 5173; открывать нужно `http://127.0.0.1:5173`. Запускать его и `npm start` одновременно не следует.

## Тесты

```bash
npm run typecheck
npm run lint
npm run test:unit
npm run test:integration   # настоящий PostgreSQL, только тестовая база
npm run test:e2e           # Playwright, отдельный тестовый сервер и база
```

Интеграционные и браузерные тесты работают с отдельной тестовой базой и собственными временными аккаунтами. Тесты не печатают пароли, cookies и содержимое приватных файлов.

## Публикация

Приложение рассчитано на запуск за reverse proxy с TLS: процесс Node слушает только `127.0.0.1`, PostgreSQL не открывается наружу. Для production нужны `NODE_ENV=production`, `DATABASE_URL`, `SESSION_SECRET` не короче 32 символов и `APP_ORIGIN` с HTTPS-адресом. Cookie сессии выставляются как `Secure`, `HttpOnly` и `SameSite=Lax`; доверие к forwarded-заголовкам включается только для известного локального прокси.

Миграции и создание администратора выполняются отдельными CLI-командами с раздельными ролями базы: миграционная роль не используется во время работы приложения.

## Ограничения

- Проект учебный: восстановления пароля нет, email и телефон не собираются.
- Демо работает без автоматических резервных копий базы, поэтому реальные пользовательские данные в него передавать не стоит.
- Физические телефоны проверялись эмуляцией нужных размеров экрана, не реальными устройствами.
- Сборка оставляет предупреждения upstream-зависимостей (комментарий PURE у Zod) и размера чанка; они не скрываются.
